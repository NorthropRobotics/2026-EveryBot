## Overview

This project uses a **command-based** robot architecture powered by WPILib. The robot features:

- **Swerve drive** — CTRE Phoenix 6 swerve drivetrain generated by Tuner X
- **Fuel (intake/launcher) mechanism** — dual TalonFX launcher rollers + TalonFX indexer
- **Climber** — single REV SparkMax brushed motor
- **Dual USB cameras** — streamed via CameraServer

## Project Structure

```
src/main/java/frc/robot/
├── Main.java                        # Entry point
├── Robot.java                       # TimedRobot lifecycle; runs CommandScheduler
├── RobotContainer.java              # Subsystem instantiation, button bindings, auton
├── Constants.java                   # All robot-wide constants (IDs, limits, percentages)
├── Telemetry.java                   # NetworkTables + SmartDashboard swerve telemetry
├── commands/
│   ├── Intake.java                  # Run intake rollers inward
│   ├── Eject.java                   # Reverse intake rollers to eject
│   ├── SpinUp.java                  # Spin launcher wheels up to speed
│   ├── Launch.java                  # Fire launcher + indexer at full speed
│   ├── LaunchSequence.java          # SpinUp (timed) → Launch sequential group
│   ├── ClimbUp.java                 # Drive climber upward
│   └── ClimbDown.java               # Drive climber downward
├── subsystems/
│   ├── CANFuelSubsystem.java        # Intake/launcher motors (3× TalonFX)
│   ├── ClimberSubsystem.java        # Climber motor (SparkMax)
│   └── CommandSwerveDrivetrain.java # CTRE swerve drivetrain subsystem
└── generated/
    └── TunerConstants.java          # Auto-generated Tuner X swerve constants
```

## Subsystems

### `CommandSwerveDrivetrain`
Field-centric swerve drive built on the CTRE Phoenix 6 `SwerveDrivetrain` base class. Configuration is generated by **Tuner X** and lives in `TunerConstants.java`.

- **Drive motors:** TalonFX (Kraken/Falcon) with open-loop voltage control
- **Steer motors:** TalonFX with closed-loop voltage control
- **Encoders:** CANcoders (FusedCANcoder feedback mode)
- **Max speed:** Configured as a fraction of `TunerConstants.kSpeedAt12Volts` (currently 100%)
- **Max angular rate:** 0.75 rotations/second (~4.71 rad/s)
- Supports SysId characterization routines (dynamic & quasistatic, forward & reverse)

### `CANFuelSubsystem`
Controls the fuel (game piece) intake and launching mechanism.

| Motor | CAN ID | Controller | Role |
|---|---|---|---|
| Left Intake/Launcher | 16 | TalonFX | Launches / intakes (CCW positive) |
| Right Intake/Launcher | 15 | TalonFX | Launches / intakes (CW positive) |
| Indexer (Feeder) | 13 | TalonFX | Feeds game piece into launcher |

All three motors use **coast** neutral mode and an 80 A stator current limit.

Motor values are exposed on **SmartDashboard** for live tuning during testing:
| Key | Default |
|---|---|
| `Intaking intake roller value` | 0.6 |
| `Intaking feeder roller value` | -0.8 |
| `Launching launcher roller value` | 0.85 |
| `Launching feeder roller value` | 0.6 |

### `ClimberSubsystem`
Controls the end-game climber using a single **REV SparkMax** driving a brushed motor (CAN ID 14).

- Smart current limit: **40 A**
- Idle mode: **Brake**
- Up power: **80%** | Down power: **-80%**

## Commands

| Command | Subsystem | Description |
|---|---|---|
| `Intake` | `CANFuelSubsystem` | Runs intake rollers inward; stops rollers on end |
| `Eject` | `CANFuelSubsystem` | Reverses intake rollers to push game piece out |
| `SpinUp` | `CANFuelSubsystem` | Spins launcher wheels up; holds indexer back slightly |
| `Launch` | `CANFuelSubsystem` | Full launch speed on all rollers |
| `LaunchSequence` | `CANFuelSubsystem` | `SpinUp` (0.75 s timeout) → `Launch` sequential group |
| `ClimbUp` | `ClimberSubsystem` | Drives climber upward at 80%; stops on release |
| `ClimbDown` | `ClimberSubsystem` | Drives climber downward at -80%; stops on release |

## Controller Bindings

### Driver Controller (Port 0 — Xbox)

| Button | Action |
|---|---|
| Left stick Y | Drive forward/backward |
| Left stick X | Strafe left/right |
| Right stick X | Rotate (field-centric) |
| **A** (hold) | Swerve brake (X-pattern) |
| **B** (hold) | Point wheels toward left-stick direction |
| **Left bumper** | Reset field-centric heading |
| Back + Y | SysId dynamic — forward |
| Back + X | SysId dynamic — reverse |
| Start + Y | SysId quasistatic — forward |
| Start + X | SysId quasistatic — reverse |

> **Note:** Driver and operator controller ports are defined in `Constants.OperatorConstants`. A second controller (port 1) is defined as the operator controller but bindings for it are not yet assigned in `RobotContainer`.

## Autonomous

A simple **drive forward** autonomous routine is implemented in `RobotContainer.getAutonomousCommand()`:

1. Reset field-centric heading to 0° (facing away from alliance wall)
2. Drive forward at 0.5 m/s for **5 seconds**
3. Idle for the remainder of the autonomous period

PathPlanner is included as a vendor dependency and can be used for more complex paths in the future.

## Telemetry & Cameras

### Telemetry
`Telemetry.java` publishes swerve drivetrain state to **NetworkTables** and **SmartDashboard**:
- Robot pose (Struct)
- Chassis speeds (ChassisSpeeds Struct)
- Individual swerve module states and positions
- Odometry frequency
- 2D mechanism visualization via `Mechanism2d`
- CTRE `SignalLogger` integration for Hoot log replay (timestamp + joystick)

### Cameras
Two USB cameras are started automatically via `CameraServer` in `RobotContainer`:

| Camera | Resolution | FPS |
|---|---|---|
| cam0 | 320×240 | 15 |
| cam1 | 320×240 | 15 |

Streams are viewable in Shuffleboard/SmartDashboard or the Driver Station camera viewer.

## Configuration & Tuning

Constants are centralized in `Constants.java` under inner classes:

### `FuelConstants`
All intake/launcher motor IDs, current limits, and percent outputs. Motor values can be tuned live via SmartDashboard — once a good value is found, update the constant in this class.

### `ClimbConstatns` *(note: typo in source)*
Climber motor ID, current limit, and up/down power percentages.

### `OperatorConstants`
Controller port assignments and drive/rotation scaling factors (0.7× and 0.8× respectively).

### `TunerConstants` (generated)
Swerve module PID gains, feedforward gains, CAN IDs, wheel offsets, and kinematics. **Do not edit manually** — regenerate using [Tuner X Swerve Project Generator](https://v6.docs.ctr-electronics.com/en/stable/docs/tuner/tuner-swerve/index.html).

## Building & Deploying

This project uses **GradleRIO** (version `2026.2.1`) with **Java 17**.

### Build

```bash
./gradlew build
```

### Deploy to RoboRIO

```bash
./gradlew deploy
```

The team number is read automatically from `.wpilib/wpilib_preferences.json`. Ensure the RoboRIO is reachable over USB or Wi-Fi before deploying.

### Simulate (Desktop)

```bash
./gradlew simulateJava
```

Desktop support is enabled (`includeDesktopSupport = true` in `build.gradle`).
